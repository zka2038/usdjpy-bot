## Why triage is needed

- **The sample's headroom is small.** On USDJPY 2007-2024, spec 004 clears the Deflated
  Sharpe hurdle up to N = 17 on prefix (N = 10 without its single 2011-03-18 trade) and
  N = 11 on postfix: about five more specs, against thirteen queued. At N = 18 neither leg
  clears (`CLAUDE.md`, trial budget). Every spec run here costs spec 004 clearance,
  retroactively.
- **A 2015-2024 window is not a fresh sample.** Most of 006-018 name HistData 2015-2024 as
  their main test. That is a subset of the sample already searched, so it is counted
  against the same N. A fresh sample is a different pair, or a period no study here has
  used (for example USDJPY daily before 2007).
- **Specs are counted, variants are not** (user decision, 2026-11-25, "revisit if specs
  converge"). The *Configs* column below is still reported: a spec with many variants has
  its own internal multiple-testing problem, which it must handle in its own bar.

Two filters the repo has established, applied below:
- **Financing.** Spot held across the 17:00 New York roll pays about 0.88 pips a night to
  IBKR's skim before the rate differential (`costs.financing_pips`; `CLAUDE.md`). The
  largest effect found here is about 2.3 pips (spec 004 prefix, DST-corrected), so
  days-to-week spot holds are taxed past anything measured. MJY futures carry no skim.
- **Power.** A test whose MDE is far above the claimed effect returns an uninformative
  null. Compute it before spending a trial.

## Categories

| Category | Meaning |
|---|---|
| **Run elsewhere first** | The mechanism is not USDJPY-specific. Discovery on other pairs (fresh samples, each with its own count); USDJPY only as a later, separately counted confirmation. |
| **Run on USDJPY, counted** | The mechanism is yen- or USDJPY-specific, so other pairs are no test of it. Runs on this sample and spends one of its remaining specs. |
| **Rewrite for MJY or park** | Holds spot across nights; dead on financing as written. |
| **Park** | Depends on another spec, or under-powered on any available sample. |
| **Do not run on this sample** | Expected null by design; spends a trial for no tradeable output. |

## Order, if accepted

1. **Cross-pair data and costs first.** Each new pair needs its own data fetch (HistData
   via a generalised `fetch_official.py`, which hardcodes `usdjpy`; or Dukascopy, never
   while the spec 004 gap-fill fetch shares its rate limit), its own spread profile (the
   synthetic ask is keyed on USDJPY's Eightcap profile), and, for non-JPY pairs, its own
   pip size (`costs.PIP` is USDJPY's 0.01). No net result is read before that exists.
2. **Spec 004 on JPY crosses.** A new spec, the same pre-declared rule on EURJPY, AUDJPY,
   GBPJPY; MOF intervention days excluded by pre-declaration. The only route to
   confirming the one surviving effect, and `HANDOFF.md` §2's highest-value next study.
3. **"Run elsewhere first" specs, one at a time,** each declaring its sample first.
4. **011** on USDJPY, counted, once the auction calendar exists.
5. **MJY rewrites** only after an MJY cost and roll model exists.

## Sign-off (2026-11-27)

**The user accepted this plan as proposed, with the amendment below**, which was raised in
the session before any cross-pair data existed. Taken together, the open questions above
are answered as follows:

- **A pair other than USDJPY is an acceptable discovery sample** for 006, 007, 008, 010 and
  015, in the categories proposed.
- **Each new pair starts its own spec count, except JPY crosses used for a yen-side
  hypothesis** (the amendment). EURJPY = EURUSD × USDJPY, so a cross's window return is
  USDJPY's return plus a USD-pair return. On a hypothesis about the yen, a cross largely
  repeats USDJPY's own mornings and is not a fresh sample. USD pairs other than USDJPY
  (EURUSD, GBPUSD, AUDUSD) do start their own counts.
- **018: not run on this sample.** **016: parked.** (Both as proposed.)
